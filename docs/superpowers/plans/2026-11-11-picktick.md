# PickTick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Ticketmaster-style site on `workers.dev` where a classroom can search events, watch a live seat map, and hold and "buy" seats with no seat ever sold twice.

**Architecture:** One Cloudflare Worker serves a React single-page app and a Hono API. D1 holds the read-only catalog and full-text search. One SQLite-backed Durable Object per event (`EventRoom`) owns that event's seats, holds, bookings and counters, and pushes changes over WebSocket.

**Tech Stack:** TypeScript, React, Vite + `@cloudflare/vite-plugin`, React Router, TanStack Query, Tailwind CSS, Hono, Zod, Drizzle ORM (D1), Durable Objects, Vitest + `@cloudflare/vitest-pool-workers`.

**Spec:** `SPEC.md` (repo root). Read it before any task.

## Global Constraints

- Must fit the Cloudflare free plan. Durable Object class uses `new_sqlite_classes`.
- Use current stable versions; check each library's current docs for setup commands and config shape rather than relying on memory.
- Hold length `HOLD_MS = 120_000`. Max holds per user per event `MAX_HOLDS = 4`. Nickname 1 to 20 characters after trimming.
- Money is integer cents. Every time comparison uses the Durable Object's `Date.now()`.
- No card fields anywhere. No accounts.
- All request input validated with Zod on the server. Nicknames rendered as text only (never `dangerouslySetInnerHTML`).
- Bindings: D1 `DB`, Durable Object `EVENT_ROOM` (class `EventRoom`), secret `RESET_SECRET`.
- Commit after each task. `git init` happens in Task 1.

## Review Focus

1. Search text containing FTS5 syntax (`"`, `*`, `-`, `:`, `(`): returns results or an empty list, never a 500. Test in Task 2.
2. Unknown event id or seat id: `404`, and no Durable Object storage is created for an event id that is not in D1. Test in Task 4.
3. Nickname that is whitespace-only, over 20 characters, or contains HTML: rejected with `400` or stored and shown as literal text. Test in Task 4.
4. Phone sleeps and the WebSocket drops: on reconnect the client replaces its state with a fresh snapshot, including the user's own holds and deadline. Test in Task 5.
5. Browser clock is wrong by minutes: the countdown still ends when the server deadline does. Test in Task 5.

## Shared types (`shared/types.ts`, created in Task 1, used everywhere)

```ts
export const HOLD_MS = 120_000;
export const MAX_HOLDS = 4;
export const EVENT_TYPES = ['concert', 'sports', 'theater', 'comedy'] as const;
export type EventType = (typeof EVENT_TYPES)[number];

export type SeatMap = { sections: { name: string; priceCents: number;
  rows: { label: string; seats: { id: string; number: number; x: number; y: number }[] }[] }[] };

export type EventSummary = { id: string; name: string; type: EventType; startsAt: string;
  venueName: string; city: string; performerName: string };
export type EventDetail = EventSummary & { description: string; performerBlurb: string; seatMap: SeatMap };

export type SeatStatus = 'available' | 'held' | 'sold';
export type SeatView = { id: string; priceCents: number; status: SeatStatus; by: string | null };
export type Stats = { granted: number; rejected: number; expired: number; sold: number };
export type Mine = { seatIds: string[]; expiresAt: number | null };
export type Snapshot = { seats: SeatView[]; stats: Stats; mine: Mine; now: number };
export type RoomMessage =
  | ({ type: 'snapshot' } & Snapshot)
  | { type: 'seats'; seats: SeatView[]; stats: Stats; now: number };

export type User = { id: string; nickname: string };
export type Booking = { id: string; nickname: string; totalCents: number; createdAt: number; seatIds: string[] };
export type HoldResult = { ok: true; expiresAt: number }
  | { ok: false; reason: 'taken' | 'limit' | 'unknown_seat' };
export type ConfirmResult = { ok: true; booking: Booking } | { ok: false; reason: 'expired' };
```

Seat ids are `"<section>-<row>-<number>"`, unique within a venue.

### Task 3: EventRoom hold logic

**Files:** Modify `src/worker/event-room.ts`. Create `test/event-room.test.ts`.

**Interfaces:**
- Consumes: `getEvent` from Task 2 (to read the seat map on first use).
- Produces these RPC methods on `EventRoom`. Every method takes `eventId` first and calls a private `ensureSeats(eventId)` that creates tables and inserts seats from the D1 seat map once; it returns `false` if the event does not exist, in which case the method writes nothing.
  - `snapshot(eventId: string, userId: string): Promise<Snapshot | null>`
  - `hold(eventId: string, user: User, seatId: string): Promise<HoldResult | null>`
  - `release(eventId: string, userId: string, seatId: string): Promise<boolean>`
  - `confirm(eventId: string, user: User, bookingId: string): Promise<ConfirmResult | null>`
  - `getBooking(eventId: string, userId: string, bookingId: string): Promise<Booking | null>`
  - `reset(): Promise<void>` (deletes holds and bookings, clears `booking_id`, zeroes stats)
- Rules:
  - A hold row with `expires_at <= Date.now()` is treated as absent everywhere. `hold` deletes stale rows for the seat it touches and counts each as `expired`.
  - `hold`: seat sold or live-held by someone else gives `taken` and `rejected += 1`; holding your own held seat again returns `ok` with the existing deadline; a fifth live hold gives `limit`. `expiresAt` is the user's existing live deadline on this event, else `now + HOLD_MS`. Success does `granted += 1`.
  - `confirm`: if a booking with `bookingId` exists for this user, return it (idempotent). Else if the user has no live holds, `expired`. Else, in one `transactionSync`, insert the booking, set `booking_id` on the seats, delete the holds, `sold += n`.
  - `getBooking` returns `null` for another user's booking.
  - No awaits between reading and writing state inside `hold` and `confirm` after `ensureSeats` completes.

- [ ] **Step 1:** Write failing tests (use `env.EVENT_ROOM.idFromName('hot')`; to expire holds, `runInDurableObject` and `UPDATE hold SET expires_at = 0`):
  - `50 users hold one seat at once: exactly one ok, 49 taken, stats.rejected === 49, stats.granted === 1` (use `Promise.all`)
  - `expired hold lets another user hold the seat, stats.expired === 1`
  - `second seat shares the first seat's deadline`
  - `fifth hold returns limit`
  - `confirm after expiry returns expired and snapshot shows no sold seats`
  - `confirm twice with the same bookingId returns the same booking; stats.sold equals seat count once`
  - `release by a non-holder returns false and the hold remains`
  - `confirm only sells the caller's seats`
  - `getBooking with another userId returns null`
  - `hold on unknown seat returns unknown_seat`; `hold on event 'nope' returns null`
  - `reset returns every seat to available and stats to zero`
- [ ] **Step 2:** Run `npx vitest run test/event-room.test.ts`. Expected: FAIL.

### Task 4: API routes, identity, live updates, reset

**Files:** Create `src/worker/identity.ts`. Modify `src/worker/index.ts`, `src/worker/event-room.ts`, `test/routes.test.ts`.

**Interfaces:**
- Consumes: Task 3 methods.
- Produces:
  - Middleware on `/api/*`: reads cookie `uid`; if missing, sets a new `crypto.randomUUID()` with `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000`. Exposes `c.get('uid')`.
  - `POST /api/events/:id/holds` body `{ seatId: string, nickname: string }` → `200 { expiresAt }`, `409` taken, `422` limit, `404` unknown seat or event, `400` invalid body.
  - `DELETE /api/events/:id/holds/:seatId` → `204`, or `404` if not the caller's hold.
  - `POST /api/events/:id/bookings` body `{ bookingId: uuid, nickname: string }` → `200 Booking`, `410` expired. (The client generates `bookingId` once per checkout; this is how "Pay twice" stays one booking. It refines SPEC section 7, which showed no body.)
  - `GET /api/events/:id/bookings/:bookingId` → `200 Booking` or `404`.
  - `GET /api/events/:id/live` → WebSocket upgrade forwarded to the room's `fetch` with the uid in header `x-uid` and the event id in `x-event-id`. The room accepts with the hibernation API, tags the socket with the uid, and sends a `snapshot` message.
  - After every successful `hold`, `release`, `confirm`, `reset`, the room broadcasts a `seats` message with the changed seats and current stats.
  - Expiry push: whenever holds exist, the room sets an alarm for the earliest `expires_at`; `alarm()` deletes expired holds, adds to `expired`, broadcasts them as available, and re-arms. Correctness never depends on the alarm.
  - `POST /api/admin/reset` with header `x-reset-secret` equal to `RESET_SECRET` → calls `reset()` on the room of every event in D1, `204`; otherwise `401`.

- [ ] **Step 1:** Write failing route tests via `SELF.fetch`, carrying the `Set-Cookie` value forward by hand:

  - `hold then hold by a second cookie returns 409`
  - `hold with nickname '   ' or 21 chars returns 400; nickname '<b>x</b>' is stored and returned verbatim in the snapshot's by field` (Review Focus 3)
  - `hold on /api/events/nope/holds returns 404; hold with seatId 'zzz' returns 404` (Review Focus 2)
  - `booking flow: hold, POST bookings → 200, GET booking → 200, GET with another cookie → 404`
  - `POST bookings with no holds returns 410`
  - `live: WebSocket first message is type snapshot; after another user's hold a seats message arrives naming that seat as held`
  - `reset without the secret returns 401; with it, a held seat is available again`
